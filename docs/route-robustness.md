# World 1-1 按键扰动恢复

从标准开局启动 1-1 专用策略。每个决策根据当前画面和状态选择动作。输入层报告外部按键覆盖时，控制器先保存检查点，执行实际覆盖输入，再恢复并继续决策。还原范围包括 NES 和 Python 观测历史。模拟器的 RAM 在恢复后逐字节校验。

## 实测

| 扰动场景 | 原策略继续游玩 | 检查点恢复 |
|---|---:|---:|
| 开局移动或跳跃覆盖 | 0/4 | 4/4 |
| 中途短时覆盖 | 2/8 | 8/8 |
| 留出单次及多次覆盖 | 1/8 | 8/8 |
| 覆盖输入导致死亡 | 0/1 | 1/1 |

所有恢复对局实际到达旗杆，最远位置 3161。每一局的正常决策 RAM 轨迹校验值均与无扰动对局一致。压力用例中，覆盖输入在第 27 个决策步导致死亡，恢复后仍通关。

正常对局离屏吞吐为 203.4 决策步/秒。含扰动注入与恢复的对局最低为 192.6 决策步/秒。共 26 次覆盖，检查点还原和校验中位耗时 0.04 毫秒，最大 0.07 毫秒。完整覆盖处理包含模拟扰动本身，中位耗时 12.8 毫秒。正常播放按 60 NES 帧/秒运行，每 4 帧做一次决策，即每秒 15 次。计时排除录像编码。

## 无回档试验

开局的四种已知失败输入通过游戏内动作对齐亚像素位置，接入另一条经过验证的通关路线，实测 4/4 通关。新增两组开局扰动为 1/2。中途无回档搜索为 5/8 通关，部分搜索耗时数秒至数十秒。以上试验和检查点结果分别统计。亚像素字段以公开的反汇编符号和本机读数核对。[NES 状态字段](https://github.com/Xkeeper0/smb1/blob/master/src/ram.asm)

## 复跑

使用之前生成的 `world-1-1-route.npz`，在项目根目录运行。

```powershell
python eval/route_robustness.py --route-model <world-1-1-route.npz> --output logs/exp_20261103_robust_01
```

这一验收适用于支持保存和恢复状态的本地模拟器，扰动通过显式的输入覆盖事件注入。逐局 JSON 保存覆盖动作、实际位移、是否在扰动中死亡、恢复延迟和通关轨迹校验值。
